# Cockpit v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Spec:** `cockpit-v2` (approved)

**Goal:** Replace the v1 tab-per-WorkItem zellij layout with a single shared cockpit tab — one fixed agent pane on the left plus a fixed, focus-driven rich stack of `mship view … --follow` panes on the right — backed by a persisted CURRENT FOCUS file.

**Architecture:** A small per-workspace focus-state file (`<state_dir>/cockpit-focus.json`) records the focused WorkItem id + a monotonic timestamp. `mship layout focus <id>` validates the id and writes that file (it no longer touches zellij tabs). A new `--follow` flag on `mship view {spec,diff,journal,item,status}` resolves the target from the focus file at render time (re-scoping when focus OR data changes), showing a clear empty/hint state when nothing is focused. `mship layout` builds ONE cockpit tab: a fixed left Agent pane (outside any stack) beside a right `pane stacked=true { … }` group of a SINGLE fixed rich set of `--follow` view panes (Spec + Diff + Journal + Status + Item/PR), the same regardless of phase — every member re-scopes to the focused item, and the operator flips through the stack. All v1 per-item-tab machinery is deleted.

**Tech Stack:** Python 3.11, Typer (CLI), Textual (TUIs), zellij 0.44.1 KDL layouts (`pane stacked=true`), pytest + `typer.testing.CliRunner`, `uv` for running tests. Dependency-injector `Container` for state/config wiring.

## Design notes (read before starting)

1. **Focus file location = per-workspace state dir.** The spec offered "`~/.cache/mship/focus`, or a workspace-state key". We use `<state_dir>/cockpit-focus.json` because (a) a machine can host several workspaces and focus must be per-workspace; (b) every `--follow` view and `mship layout focus` runs inside the workspace (the cockpit panes inherit the workspace-root cwd), so `container.state_dir()` resolves it for free; (c) it matches how all other mship state is stored. A monotonic `updated_at` timestamp is stored so re-focusing the *same* id still registers as a change.

2. **ac4 (dynamic per phase) is satisfied by ONE fixed rich stack that follows focus — RESOLVED by the operator (option A).** The right-side stack is a single fixed member set — **Spec + Diff + Journal + Status + Item/PR** — the same regardless of the focused item's phase. There is NO phase-conditional membership and NO rebuild on focus change. ac4's "dynamic per phase" is met because every member runs `--follow` and re-scopes to the focused item, and each view renders phase-appropriate content (or its own empty/hint state) for whatever the focused item currently is: in Plan the Spec pane carries the spec while Diff/Journal/Status show "waiting for a task"; in Dev/Review those populate; the Item pane always carries the PR/checks composite. The operator flips through the always-available rich stack (zellij stacked panes are discoverable/flippable — the v1 pain point). This also makes ac5 trivial: switching WorkItems only rewrites the focus file; the running `--follow` panes re-scope on their next tick and the Agent pane is never touched. The KDL is never rewritten on a focus change.

3. **zellij stacked-pane syntax.** Verified against zellij 0.44.1 (local): a stacked group is `pane stacked=true { pane … pane … }`. Child panes may carry their own `command=`/`args`. The Agent pane is a **sibling** of the stacked group inside a `pane split_direction="vertical" { … }`, so it is fixed and outside the stack. (Live layout-parse validation is unreliable in this nested-zellij shell; the KDL is unit-tested as strings, mirroring the existing `tests/cli/test_layout.py` style, plus a manual `mship layout launch` smoke test in Task 11.)

4. **Actual view-command facts (verified in code, not assumed):**
   - The run/journal view is `mship view journal` (registered in `cli/view/logs.py`); **there is no `mship view logs`.**
   - `mship view item <id>` (alias hidden `workitem`) is a `MasterDetailApp` with **no watch loop** — Task 8 adds a periodic refresh for `--follow`.
   - `spec`, `diff`, `journal`, `status` are `ViewApp` stream views with a per-tick `gather()`/`_refresh_content()`; `--watch` drives the interval. `--follow` reuses that loop.
   - `DiffView` already supports a per-tick `resolve_paths` closure + `header_provider`; `diff --follow` needs only CLI wiring (no view-class change).
   - `spec` already has `--workitem`/`--status`/`--task`/`name` selectors that are mutually exclusive; `--follow` joins that exclusion set.

# src/mship/core/focus.py
"""Persisted CURRENT FOCUS for the v2 cockpit (spec cockpit-v2, ac1).

A tiny per-workspace file holding the focused WorkItem id + a monotonic
timestamp. Pure over a Path — no container, no Textual — so it is unit-testable
directly. `mship layout focus` writes it; `mship view … --follow` reads it.
"""
from __future__ import annotations

import json
from dataclasses import dataclass
from datetime import datetime, timezone
from pathlib import Path

FOCUS_FILENAME = "cockpit-focus.json"


@dataclass(frozen=True)
class FocusState:
    work_item_id: str
    updated_at: datetime


def focus_path(state_dir) -> Path:
    """The focus file inside a workspace's state dir."""
    return Path(state_dir) / FOCUS_FILENAME


def write_focus(path: Path, work_item_id: str, *, now: datetime | None = None) -> FocusState:
    """Record `work_item_id` as focused with a monotonic UTC timestamp; returns the
    written state. Creates parent dirs so the first focus in a fresh workspace works."""
    ts = now if now is not None else datetime.now(timezone.utc)
    path = Path(path)
    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_text(
        json.dumps({"work_item_id": work_item_id, "updated_at": ts.isoformat()}) + "\n"
    )
    return FocusState(work_item_id=work_item_id, updated_at=ts)


def read_focus(path: Path) -> FocusState | None:
    """Read the focus state, or None when the file is absent/unreadable/malformed —
    a missing or corrupt focus file must degrade to 'no focus', never raise."""
    try:
        raw = Path(path).read_text()
    except (FileNotFoundError, OSError):
        return None
    try:
        data = json.loads(raw)
        work_item_id = data["work_item_id"]
        updated_at = datetime.fromisoformat(data["updated_at"])
    except (ValueError, KeyError, TypeError):
        return None
    if not isinstance(work_item_id, str) or not work_item_id:
        return None
    return FocusState(work_item_id=work_item_id, updated_at=updated_at)
```

    def focus(
        item_id: Optional[str] = typer.Argument(
            None, help="WorkItem id to focus (e.g. wi-...)."),
        show: bool = typer.Option(
            False, "--show", help="Print the current focus and exit."),

        Writes the focus file — it does NOT open/switch a zellij tab; the cockpit's

        from mship.cli.view._workitems import load_workitem_index

        container = get_container()
        state_dir = container.state_dir()

        if show:
            current = read_focus(focus_path(state_dir))
            if current is None:
                typer.echo("No WorkItem focused. Run `mship layout focus <id>`.")
            else:
                typer.echo(f"Focused: {current.work_item_id}")
            return

        if item_id is None:
            typer.echo("Error: provide a WorkItem id, or --show.", err=True)
            raise typer.Exit(code=1)

        summary = next((s for s in load_workitem_index(container) if s.id == item_id), None)
        if summary is None:
            typer.echo(f"Error: unknown work item: {item_id}", err=True)
            raise typer.Exit(code=1)

        write_focus(focus_path(state_dir), item_id)
        if summary.phase == "done":
            typer.echo(f"Focused {item_id} (note: this item is done).")
        else:
            typer.echo(f"Focused {item_id}.")
        if not _in_zellij():
            typer.echo("Not inside a zellij session; run `mship layout launch` "
                       "to open the cockpit. (focus recorded)")

# src/mship/cli/view/_follow.py
"""Shared `--follow` resolution for the view commands (spec cockpit-v2, ac2).

`--follow` points a view at the workspace CURRENT FOCUS (written by
`mship layout focus`) instead of a fixed --task/--workitem, re-resolving at render
time so a focus change re-scopes the pane. This module owns the two shared pieces:
reading the focused id from the focus file, and the single empty-state hint string
every follow view shows when nothing is focused.
"""
from __future__ import annotations

from mship.core.focus import focus_path, read_focus


def read_focused_id(container) -> str | None:
    """The currently-focused WorkItem id for this workspace, or None when nothing
    is focused (or the focus file is missing/corrupt)."""
    state = read_focus(focus_path(container.state_dir()))
    return state.work_item_id if state is not None else None


def follow_hint() -> str:
    """The clear empty state shown by a `--follow` view when no WorkItem is focused
    (ac2) — never an error."""
    return ("No WorkItem focused. Press enter on an item in the Overview tab, "
            "or run `mship layout focus <id>`.")
```
