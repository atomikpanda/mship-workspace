# Host tunnel registration (#471) — implementation plan

> Spec: `specs/2026-08-17-host-tunnel-registration-471.md` (mship spec `host-tunnel-registration-471`) · GitHub issue: atomikpanda/mothership#471 · Parent: #469 · Builds on merged #470 and #472 (PRs #476 / GC #67).
> Produced by an ultracode workflow (6 readers → 2 opposed drafts → judge → 3 adversarial verifiers; 38 verified findings folded in, incl. 6 blockers — the "no relay-config change" claim was false (the Caddy enroll site 404s everything but /enroll and /status/*), both clone nets missed the common `cp -a` clone, and TunnelSupervisor's backoff overflows at restart_count 1024, reachable only now that an immortal daemon owns it).

# Implementation Plan

## Assumption header — disposed of explicitly

1. **Metarepo/cross-repo (the #444 blind spot).** #471 is host-level and workspace-agnostic: the tunnel carries bytes identically for every workspace shape, so there is no per-shape transport logic to get wrong. The one place a shape could leak in is the subdomain derivation — and it is being moved **off** any workspace input (`device_subdomain(workspace, …)` → `host_subdomain(host_id, …)`), which *removes* the last shape dependency rather than adding one. **No task below may take a workspace name, path, repo list, or `git_root` as an input**, enforced by a grep/AST invariant test in Task 1. The two places shape can still surface are payload projections, and both get a metarepo fixture, not just single-repo: (i) `GET /workspaces` must pass a metarepo entry's `repos: list[RepoInfo]` through unchanged alongside the new `runner` field; (ii) GC's ladder function must produce the same states for a metarepo connection. Reuse `tests/core/daemon/test_discovery.py`'s `_mk_metarepo` builder — do not write a new one. The corollary for reviewers: there is deliberately no per-shape matrix elsewhere, and that absence is this assumption, not an oversight.
2. **"Reuse the relay surface" is read strictly.** The transport is the existing `ssh -R` into sish; the trust root is the existing enroll/`pubkeys/` allowlist; the host directory lands on the **already-supervised** enroll-server (`mship-relay-enroll.service`, `docs/relay-hosting.md:156-179`), which already owns an atomic on-disk store (`RequestStore`). *(It does **not** host the cloud-worker grant/run-token surface — that is a separate `mship relay egress-server` process on 127.0.0.1:47280 with its own store dirs and its own `egress.<relay>` site; colocation is justified by supervision + store reuse alone.)* No new port, container, DNS record, or relay service — but **one Caddy matcher is required** (AC13), because the enroll site's 404 catch-all would otherwise swallow every new route.
3. **The host subdomain needs no relay TLS change.** `host_subdomain` produces `<base32-12>-<6hex>`, which already satisfies `_SERVE_LABEL = [a-z0-9][a-z0-9-]*-[0-9a-f]{6}` (`core/relay/tls_ask.py:8`). Verified by reading the regex; pinned by a test in Task 1. This is the largest reuse win and the reason "relay redeploy touches no host" falls out cheaply.
4. **The ed25519 relay key is already per-machine, non-interactive, and already the ssh identity** (`core/relay/keys.py` `ensure_relay_key`). #471 gives it a second job (signing registrations) rather than minting a second credential — that is what makes the auth end-to-end: the relay verifies against the *same* allowlist sish authenticates against. It is also *clonable*, which is why identity does not rest on it (assumption 10).
5. **`TunnelSupervisor` is reused with exactly one fix** (`core/relay/tunnel.py`): tick-driven, zero threads/sleeps inside, injectable `proc_factory`/`clock`, capped-exponential backoff with no retry ceiling — the policy is already the AC. The fix: `self._backoff_delay * (2 ** self._restart_count)` (line 170) raises `OverflowError: int too large to convert to float` at `restart_count == 1024` (verified in this tree: 1023 → 60.0, 1024 → raises), and `_restart_count` is reset only by `start()`, never after a healthy run. Under a CLI thread that dies with the shell this was unreachable; under an immortal daemon a 60s-capped flap reaches it in ~17 hours. The exponent is clamped (and jitter added, assumption 11). #471 also changes the supervisor's *owner* (CLI thread → daemon asyncio task), not its policy.
6. **Identity lands before transport.** Tasks 1–3 are pure and dependency-free; if Tasks 6+ were cut, the host would still have a correct identity and a correct short-lived-token auth model, and the "relay must not assert identity" / "no interactive entry at boot" properties would already be settled.
7. **This is a feature**, so this plan is the gate artifact: save and commit it at the **workspace root** `docs/plans/`, not in the task worktree.
8. **Every task is failing-test-first, and no test may bind a real port or sleep in real time.**
9. Work happens in `mothership` except Task 10 (`ground-control`) and half of Task 11. Dependency order 1→…→9, then {10, 11}; Tasks 4–5 (relay side) and 6–7 (daemon side) are independent once 1–3 land.
10. **A clone copies every file, including `/etc/machine-id`.** Machine fingerprints catch re-imaging, not `cp -a`. Every clone claim in this plan therefore rests on the in-memory `instance_id` plus relay-side arbitration; the fingerprint is a corroborant that makes re-identification *earlier*, never the discriminator.
11. **Nothing in a fleet may retry in lockstep.** `ServerAliveInterval 30`/`CountMax 3` makes every host detect a sish recreate within the same ~90s window, and a purely deterministic `5 * 2^n` schedule keeps them phase-locked forever. Backoff and `REGISTER_INTERVAL_S` both carry an injected-RNG jitter factor so tests stay deterministic and production disperses.

## Decisions (one line of rationale each)

**(a) What carries host identity, and where its secret lives.**
Identity is **minted and machine-bound, never derived**, because a derived id is exactly what makes a clone invisible — and *liveness* identity is per-process, because everything on disk is clonable.

| Thing | Value | Location | Reused from |
|---|---|---|---|
| Cryptographic identity | ed25519 keypair — signs registrations **and** authenticates the ssh tunnel; **rotated on re-identify** | `~/.mothership/relay_ed25519` (0600) | `keys.ensure_relay_key` — unchanged |
| Logical identity | `host_id = hst-<unix-ts>-<uuid8>`, minted once, re-mintable | `~/.mothership/daemon/host-identity.json` (0600), alongside `machine_fingerprint`, `created_at`, `cloned_from` | mirrors `registry.mint_workspace_id` / the workspace id file |
| **Liveness identity** | `instance_id` = 16 random hex, minted **in memory at daemon start**, deliberately never persisted | process only (published in `/health` + registrations) | new — the one value a clone cannot copy |
| Clone corroborant | `machine_fingerprint = sha256` of the first readable of `/etc/machine-id`, `/var/lib/dbus/machine-id`, macOS `IOPlatformUUID`; `None` in containers | **recorded inside** the identity file at mint | new |
| Subdomain | `host_subdomain(host_id, device_id(pubkey), secret)` | derived | `tunnel.opaque_slug`/`device_subdomain` verbatim, `host_id` in the workspace slot |
| Subdomain HMAC secret | 32 random bytes | `~/.mothership/relay-subdomain-secret` | `keys.ensure_subdomain_secret` — unchanged |
| Phone-facing bearer | short-lived `<token_id>.<secret>`, hash-only at rest | `~/.mothership/daemon/host-tokens.json` | `run_token.py` shape |
| Phone-facing refresh | per-client record, hash-at-rest, revocable, **stable across re-registration** | `~/.mothership/daemon/host-refresh.json` | `run_token.py` / `enroll.RequestStore` shape |

Recording the fingerprint *inside* the identity file catches a re-imaged host **before the daemon ever dials**. It does **not** catch a `cp -a` clone, which reproduces it — that case is caught on the wire by `instance_id` contention plus the relay's arbitration probe of the incumbent (decision **f**).

**(b) Host tunnel vs `mship serve --relay`: coexist, unchanged.** They occupy disjoint subdomain namespaces (`opaque_slug(host_id)` vs `opaque_slug(workspace_name)`, a collision would require an HMAC preimage), so both can run on one box on one key, and ripping out the per-workspace path is a migration with no AC behind it.

**(c) Tunnel supervision as an asyncio task inside `run.py`'s existing loop, with one shared stop signal.** `_serve_forever` (`core/daemon/run.py:89-107`) currently branches between a bare `uvicorn.run` and an `asyncio.gather` of two servers; it is refactored to **always** take the asyncio branch, so supervision is not accidentally coupled to `serve_cfg is not None`. An asyncio task, not a thread, because it gives single-loop cancellation, no daemon-thread leak past `asyncio.run`, and a `finally` that runs before `history.append_clean_stop`. **Critically, the loop's stop condition is a shared `asyncio.Event` (or the servers' `should_exit`), and the tasks are joined with `asyncio.wait(..., return_when=FIRST_COMPLETED)` + cancel-and-await** — a bare `gather` would hang forever on SIGTERM (uvicorn's handlers set `should_exit`; nothing would set the tunnel loop's flag), so systemd would SIGKILL the daemon, `tunnel.stop()` and `append_clean_stop` would never run, and the `start_new_session=True` `ssh -R` child would survive as an orphan holding the subdomain — reintroducing the exact collision Task 7's reaper exists to clean up, on every restart.

**(d) Ground Control gets a first-class `HostConnection`, and migration is non-destructive adoption *on verified identity*.** The host token stops being copied into N workspace rows (`deriveConnection` does that today) because rotating a short-lived credential must be a one-row write. The legacy manual row is **adopted in place** — keeping its local `id`, `colorOverride`, and `glyphOverride`, gaining `hostId`/`workspaceId`/`state` — but adoption cannot key on the workspace *name* (#472 exists because names are ambiguous), so it probes the manual row's own `GET /health` + `GET /workspaces` and merges only on an exact `(host_id, workspace_id)` match. And because `baseUrl` becomes **derived** from `(host.publicUrl, workspaceId)` while `notify/DeepLinkResolver.resolve` matches on `normalizedBaseUrl(it.baseUrl)` and `AndroidNotifier` bakes the old URL into already-issued `PendingIntent`s, keeping the row `id` is *not* sufficient: the adopted row carries a `legacyBaseUrls: List<String>` the resolver, `upsertConnection`'s fallback, and the client's reachability preference all consult — which also keeps a LAN/tailnet-reachable workspace working when the relay is down.

**(e) Relay-box work is four one-time commands; everything else is daemon-side.** On the relay box: `uv tool install --force --no-cache <mothership>` + `systemctl restart mship-relay-enroll.service`; **`docker compose up -d --force-recreate caddy`** (or `caddy reload`) to pick up the one new `@hosts` matcher; `mship relay fleet-token --label <device>` once per phone (scan its QR into GC); and the existing `mship relay approve <id>` per new VM — with `docker/relay/docker-compose.yml`, sish flags, DNS, ports, and `tls_ask.py` explicitly unchanged. `docker/relay/Caddyfile` **does** change, by exactly one matcher block.

**(f) Restart vs clone is arbitrated by probing the incumbent, not by comparing timestamps.** A legitimate daemon restart and a booted clone both present a *new* `instance_id` against a fresh entry, so a timestamp rule would either brick every restart or admit every clone. The relay therefore probes the incumbent's published public URL: alive and answering with the incumbent's `instance_id` → `409 duplicate-identity`; unreachable, or answering with the claimant's own `instance_id` → takeover. If both twins are live on one subdomain sish splits traffic and the probe is a coin flip — which is honest, and is why the daemon-side read-back (`contended`) is the third net.

**Why the bearer is single-clock (AC10).** The host mints it and the host verifies it; the relay only *carries* the refresh credential and the phone only *presents* it. No clock but the daemon's participates in bearer validity, so the only residual hazard there is a wall-clock step on the VM, handled by an epoch-tagged monotonic anchor plus a discontinuity-triggered skew grace. Freshness decisions that *are* cross-machine — `last_seen`, `DIRECTORY_STALE_S`, challenge expiry — are stamped by the relay, never by the host, so a skewed VM cannot render itself offline or takeover-eligible. (The alternative — publishing a live bearer into the relay directory and re-listing on 401 — was rejected because it makes relay-directory freshness a dependency of phone→host auth even on a LAN, coupling two failure domains #471 exists to separate.)
