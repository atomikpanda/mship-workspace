## Problem

From GitHub GC#31: the operator wants richer, native Android notifications — conversation context in the shade, the ability to reply from the notification shade or a WearOS watch (Android Conversations / MessagingStyle), and ideally choice-response buttons. The must-have is free-text reply with conversation context. Today (per the exploration of the `notify/` package) notifications are plain BigTextStyle with only subject + last-message preview and no reply action.

## User story

As the operator, my needs-you notifications look like a chat thread with recent context, I can tap a decision's top options right in the notification OR type a free-text reply from the shade or my watch — without opening the app — and the agent receives it on the right thread.

## Approach

Ground-Control-only; no new deps or permissions (core-ktx has it all), minSdk 26. Scope = Slice 1 + Slice 2 (bubbles deferred). Decisions baked in from the exploration (operator may tweak on review): top-2 choice-actions + free-text fallback; multi-select → reply-only; one conversation per thread; expedited-Worker reply delivery; raw text in the shade.

1. **MessagingStyle + context (ac1, ac2)** — rewrite `AndroidNotifier` to build `MessagingStyle` from the thread's last ~5-6 messages (me/agent `Person`s), and push a long-lived dynamic conversation shortcut per thread (`ConversationShortcuts` helper), setting `shortcutId`/`locusId` on the notification. Enrich `NeedsYouEvent` (`messages`, `decision`) and have `NeedsYouReconciler` fetch the full `Thread` (`SpecApi.getThread`) before notifying (gated by the existing dedupe store), keeping `AndroidNotifier` a pure render step.
2. **Inline direct-reply (ac3, ac6)** — add a `RemoteInput` reply action → a new `ReplyReceiver` (exported=false) that enqueues an expedited `OneTimeWorkRequest` (`ReplyWorker`) to resolve the `WorkspaceConnection` by connId and POST via the existing `SpecApi.postMessage`; on success re-notify with the message appended (clears the reply spinner), on failure re-notify keeping the action + an error line. WearOS gets reply for free.
3. **Choice-action buttons (ac4, ac5)** — for single-select decisions, build up to 2 option Actions (recommended first) posting the raw option text via the same receiver path (bypasses the free-text gate exactly as in-app); multi-select → no buttons (reply-only). Free-text Reply always present as the catch-all.

Manifest: register `ReplyReceiver` (exported=false); no new permissions. Tests: unit-test the pure pieces (timestamp parsing, action-building from a Decision, RemoteInput→post-body mapping, reconciler enrichment via the existing MockEngine + FakeNotifier) + `mship build` (assembleDebug). Slice order if we split PRs: MessagingStyle+context+reply first, choice-actions second — but bundled here per the operator.
