## Problem

From MOS-224 (recorded decision 2026-07-09): Ground Control is intentionally quieter than chatty agents, which leaves the operator parked at "Awaiting reply" with no sense of whether the agent is actually working. The recorded hybrid decision: the thread shows a lightweight activity/status strip (recent journal/action) so it isn't a black box, while the full picture lives on the WorkItem + Home queue; and — as a follow-on — build journaling into more built-in `mship` commands so agents emit progress automatically. This spec is the GC-only v1: the in-thread activity strip.

## User story

As the operator, when I'm waiting on an agent in a thread, I can see a slim activity strip showing its latest task journal action ("wrote parser · 3m ago") — so "Awaiting reply" tells me something's happening (or isn't), without opening the app's task views.

## Approach

Ground-Control-only; no server change. The pieces already exist: a `Thread` carries `task_slug`, and serve exposes `GET /journal/{slug}`.

1. **Fetch** — in the conversation flow (`ui/messages/ConversationViewModel` / `ThreadsRepository` / `MshipClient`), when the thread has a `task_slug`, fetch `GET /journal/{slug}` on open and refresh it on the existing conversation poll (reuse the cadence — no new tight loop). Add a `MshipClient.getJournal(conn, slug)` + DTO for journal entries (entry text, action, timestamp).
2. **Render** — a slim activity strip in `ConversationScreen` (placement per q1) showing the latest action (or last 2-3, per q2) + a relative time, styled subordinate to messages. No strip when `task_slug` is null; graceful empty state.
3. **No mothership change** — v1 relies entirely on the existing `/journal/{slug}` + `task_slug`. The "auto-journal in more built-in commands" half of the decision is a separate mothership follow-on (so the strip gets richer automatically over time).

Testing: JVM unit tests for the journal DTO parse + the VM fetch/merge (existing MockEngine pattern); `mship build` (assembleDebug). Small, contained, and it makes the quiet-by-design threads legible.
