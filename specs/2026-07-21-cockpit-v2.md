## Problem

The v1 cockpit gives each WorkItem its own zellij tab, and every per-item tab carries its own agent pane. That is the wrong frame for agentic engineering: one agent (this session) drives the whole workspace and should stay fixed on the left, but zellij cannot share a pane across tabs, so a tab-per-WorkItem forces a separate agent per tab. Phase views were nested as zellij swap sub-tabs that were not discoverable or easy to flip, and the per-phase view sets were a fixed 1:1 rather than dynamic (in-flight work needs more views than, say, Plan). The net effect: the cockpit does not match how people actually work, and switching WorkItems means re-arging panes because MSHIP_TASK is per-shell and does not cross zellij panes.

## User story

As someone doing agentic engineering across many WorkItems, I want a single fixed agent pane on the left and a right-side view area that re-scopes to whichever WorkItem I focus, with phase views I can flip through, so that I can pivot between WorkItems and phases without ever losing or restarting my agent and without re-arging every pane.

## Approach

Introduce a workspace-level CURRENT FOCUS: a persisted focus-state file naming the focused WorkItem id. `mship layout focus <id>` sets it (it no longer opens or switches a zellij tab); `mship layout focus --show` prints the current focus. Add a `--follow` mode to the relevant `mship view` commands (spec, diff, journal, item, status) that resolves the CURRENT FOCUS instead of a fixed --workitem/--task and re-renders when the focus changes or the underlying data changes, showing a clear empty/hint state when no focus is set. The cockpit layout becomes ONE shared tab: LEFT is a single agent pane running a configurable command (default: a shell in the workspace root), fixed and never in any swap/stack so it is never restarted; RIGHT is a zellij STACKED pane group of the focused item's phase views (Plan/Dev/Review/Run) so collapsed phases show as title bars and the operator flips through them with zellij stack navigation. The per-phase view sets are dynamic (not 1:1), tuned per phase: Plan shows the spec + open questions; the in-flight/Dev phase shows the richest set (diff + journal + status); Review shows diff + PR/checks; Run shows the journal. Switching WorkItems re-scopes the whole right side (all --follow panes) and is driven both by picking an item in the Overview items picker (enter = set focus) and by `mship layout focus <id>` from the CLI/agent. The v1 per-item-tab machinery (render_workitem_layout tab-per-item creation, the new-tab/go-to-tab/close-tab focus flow, and close-on-done tab teardown) is removed and superseded by the single-cockpit + focus model.

## Architecture

CURRENT FOCUS is a small persisted file (e.g. ~/.cache/mship/focus or a workspace-state key) holding the focused WorkItem id and a monotonically-updated timestamp. `mship layout focus <id>` validates the id against the WorkItem index and writes the file; `--show` reads it. The `--follow` view mode resolves the focused id at render time and watches the focus file (mtime/inotify-style poll consistent with the existing --watch loop) so a focus change re-scopes the pane; it also keeps the existing --watch data refresh. The cockpit KDL is a single tab: a left agent pane (configurable command via MSHIP_CHAT_COMMAND, default a shell cd'd to the workspace root) plus a right zellij stacked pane group whose members are the per-phase composite view panes, each running `mship view <cmd> --follow`. Because the agent pane lives outside the stack, flipping phases (zellij stack navigation) and switching focus never touch it. The Overview launchpad tab (queue + items) stays; the items picker's enter action becomes set-focus rather than open-tab. render_workitem_layout and the tab-per-item focus/close flow from v1 are deleted.

## Testing

Pure/units: focus-file read/write + validation (set/show/unknown/done); the --follow resolution (focus set -> scopes to item; no focus -> empty state; focus change -> re-scope) with the file behind a seam; the cockpit KDL builder (single tab, left agent pane not in the stack, right stacked group with the four phase composites, dynamic per-phase view sets). CLI: `mship layout focus`, `--show`, and the items-picker enter=set-focus path. Zellij visual behaviour (stack flipping, agent persistence) is validated by the operator since it cannot run headlessly in CI; the KDL structure assertions stand in for it.
